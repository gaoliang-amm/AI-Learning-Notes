# 问题与优化

> 本项目常见问题、优化路径、以及扩展方向。

---

## 常见问题

### 1. 过拟合

**现象：** 训练 loss 持续下降，但测试 loss 开始上升，准确率停滞。

**原因：** BERT 参数量大（110M），数据量不够大时容易过拟合。

**解决思路：**

| 方法 | 做法 | 效果 |
|------|------|------|
| Early Stopping | 监控验证集 loss，连续 N 个 epoch 不降就停 | 最简单有效 |
| Dropout | BERT 内置 dropout，也可以在分类头加 | 正则化 |
| 冻结底层 | 只训练最后 2-3 层，冻结底层 | 减少可训练参数 |
| 数据增强 | 同义词替换、回译 | 增加数据多样性 |

### 2. 标签不平衡

**现象：** 正面评论远多于负面（或反之），模型偏向多数类。

**原因：** 电商评论天然正面多（用户更愿意晒好评）。

**解决思路：**

| 方法 | 做法 |
|------|------|
| 分层抽样 | 本项目已用，train/test 标签比例一致 |
| 加权损失 | BCEWithLogitsLoss 传 `pos_weight` 参数 |
| 过采样/欠采样 | 对少数类过采样或多数类欠采样 |
| Focal Loss | 对难分类样本给更大权重 |

### 3. Padding 效率

**现象：** batch 内句子长短差异大，短句子被 pad 到最长，浪费计算。

**原因：** 静态 padding 的问题。

**解决：** 本项目已用 `DataCollatorWithPadding` 做动态 padding，按 batch 内最大长度 pad，而非全局 512。

## 优化路径

### 短期优化（可直接加）

| 优化 | 做法 | 预期收益 |
|------|------|---------|
| 学习率调度 | 加 `get_linear_schedule_with_warmup` | 训练更稳定，收敛更快 |
| 换 AdamW | `torch.optim.AdamW` 替代 Adam | 权重衰减更合理，泛化更好 |
| 梯度裁剪 | `torch.nn.utils.clip_grad_norm_` | 防止梯度爆炸 |
| 混合精度 | `torch.amp` 自动混合精度 | 训练速度提升 1.5-2x |

### 中期优化（需要改造）

| 优化 | 做法 |
|------|------|
| 数据增强 | 同义词替换、EDA、回译 |
| 对抗训练 | 加 FGSM/PGD 扰动，提升鲁棒性 |
| 模型蒸馏 | 用大模型蒸馏小模型，部署更轻量 |
| 更大模型 | 换 bert-base 到 RoBERTa-wwm-ext 或 MacBERT |

### 代码质量优化

| 问题 | 改进 |
|------|------|
| evaluate.py 变量命名 | `train_loader` 应改为 `test_loader`（功能没错，可读性差） |
| 硬编码路径 | 用 `config.py` 统一管理，或用 Hydra 做配置 |
| 无日志系统 | 加 Python logging 替代 print |

## 扩展方向

### 多分类
把正/负面扩展为"正面/中性/负面"三分类，或更细粒度的 5 级情感。改动：`num_labels` 改成 3 或 5，损失函数保持不变。

### 多标签
一条评论可能同时包含多个情感维度（如"物流快但质量差"）。改动：损失换成 `BCEWithLogitsLoss`（多标签版），输出每个标签独立概率。

### 跨语言
用 `bert-base-multilingual-cased` 替换 `bert-base-chinese`，支持中英文混合评论。改动：换模型名，其余不动。

### 部署上线
- 用 FastAPI 封装成 REST API
- 用 ONNX Runtime 加速推理
- 用 Docker 容器化部署
