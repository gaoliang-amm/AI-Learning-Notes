# 面试追问

> 12 个高频追问 + 标准答案，覆盖模型原理、损失函数、工程细节、优化方向。

---

## Q1: 为什么用 CLS 向量做分类？

**标准答案：**

BERT 预训练时设计了两个任务：MLM（掩码语言模型）和 NSP（下一句预测）。NSP 任务让 CLS token 学会了汇总整句语义信息。所以做句子级分类时，取 CLS 的输出向量（768 维）是标准做法。

实际操作是 `outputs.last_hidden_state[:, 0, :]`，取第 0 个位置的向量。

**追问方向：** 如果面试官问"能不能用其他方式？"——可以用 mean pooling（所有 token 输出取平均），某些任务上效果更好，但 CLS 是最直接的。

---

## Q2: 为什么学习率用 1e-5？

**标准答案：**

BERT 有 110M 参数，大部分已经预训练好了。微调的本质是在预训练知识基础上做小幅调整。学习率太大（比如 1e-3）会破坏预训练权重（灾难性遗忘），太小（比如 1e-7）收敛太慢。1e-5 是经验值，在保留预训练知识和适应新任务之间取得平衡。

一般 BERT 微调的 lr 范围是 2e-5 到 5e-5，我用 1e-5 偏保守但稳定。

---

## Q3: sigmoid 和 softmax 的区别？

**标准答案：**

sigmoid 把单个实数映射到 (0,1)，适合二分类输出一个概率值。softmax 把 N 个 logits 变成概率分布（加起来为 1），适合多分类。

本项目 V1 输出标量 `(batch_size,)`，用 sigmoid。V2 输出两列 `(batch_size, 2)`，用 softmax 取第 1 列。

**数学等价性：** 二分类时，sigmoid(x) = softmax([0, x])[1]，结果完全一样。

---

## Q4: V1 和 V2 的核心区别是什么？

**标准答案：**

本质区别是**谁来定义模型和损失**。

V1 自己写 `ReviewAnalyzeModel`，手动接 `nn.Linear(768, 1)`，手动用 `BCEWithLogitsLoss`，手动 `torch.save(state_dict)`。

V2 用 `AutoModelForSequenceClassification`，模型和损失全内置，用 `save_pretrained` 保存。

V1 让我理解了 BERT 内部工作方式，V2 更接近工程实际。两版效果基本一致。

---

## Q5: 为什么两版效果一样？

**标准答案：**

因为数学上等价。V1 的 `nn.Linear(768, 1)` + `BCEWithLogitsLoss` 和 V2 的内置 `nn.Linear(768, 2)` + `CrossEntropyLoss`，在二分类场景下优化目标相同。模型初始化、数据、训练策略都一样，所以收敛到的结果也一样。

区别只在于代码组织方式，不影响模型行为。

---

## Q6: 动态 padding 比静态 padding 好在哪？

**标准答案：**

静态 padding 把所有句子 pad 到固定长度（比如 512），不管实际句子多短。动态 padding 按 batch 内最长句子 pad。

假设 batch 内最长句子 128 tokens，静态 pad 到 512 意味着 75% 是无用 padding。这些 padding 位置在 attention_mask 中被标记为 0，不参与注意力计算，但矩阵运算本身还是要做的。动态 padding 省 40-60% 计算量和显存。

实现方式：用 `DataCollatorWithPadding`，它会在 collate 时按 batch 内最大长度 pad。

## Q7: BERT 微调为什么不用更大的 lr？

**标准答案：**

两个原因：

1. **灾难性遗忘**：BERT 的预训练权重编码了大量语言知识。大学习率会让梯度更新幅度过大，覆盖掉这些知识，模型从"有知识"退化为"从头学"。

2. **Loss landscape**：预训练好的模型已经在参数空间的一个好位置，附近是相对平坦的最优区域。大学习率容易跳出这个区域，反而变差。

经验上 2e-5 到 5e-5 是安全范围，1e-5 偏保守。

---

## Q8: 交叉熵 vs 二元交叉熵？

**标准答案：**

- **CrossEntropyLoss**：用于多分类，输入是 N 个 logits，输出是各类概率分布。
- **BCEWithLogitsLoss**：用于二分类/多标签，输入是单个 logit（或多个独立 logit），输出是每个标签的独立概率。

本项目 V1 输出标量，用 BCEWithLogitsLoss。V2 输出两列 logits，用 CrossEntropyLoss。

**数学等价性：** 二分类时，CrossEntropyLoss(p) = BCEWithLogitsLoss(logit)，结果一样。区别只是输入格式不同。

BCEWithLogitsLoss 内部包含 sigmoid，CrossEntropyLoss 内部包含 softmax，都是为了数值稳定（避免手动算 exp 溢出）。

## Q9: 如何处理标签不平衡？

**标准答案：**

本项目用了**分层抽样**，保证 train/test 标签比例一致，避免测试集标签偏斜。

如果训练集本身不平衡，还有几个方法：

1. **加权损失**：`BCEWithLogitsLoss(pos_weight= torch.tensor([2.0]))`，少数类权重更大
2. **过采样**：对少数类样本复制或增强
3. **欠采样**：丢弃部分多数类样本
4. **Focal Loss**：对难分类样本给更大权重，自动聚焦困难样本

实际中先看不平衡程度，不严重就分层抽样够了，严重就加权损失。

## Q10: 为什么用 Adam 而不是 SGD？

**标准答案：**

Adam = 动量 + 自适应学习率。它对每个参数单独调整学习率，稀疏梯度的参数更新幅度更大，适合 BERT 这种参数量大、梯度稀疏的场景。

SGD 所有参数用同一个学习率，对 BERT 微调效果差很多。实际工程中一般用 AdamW（Adam + 解耦权重衰减），比纯 Adam 泛化更好。

---

## Q11: 模型保存和加载有什么区别？

**标准答案：**

V1 用 `torch.save(model.state_dict(), 'model.pt')`，保存的是权重字典。加载时需要先创建模型对象，再 `load_state_dict`。优点是灵活，缺点是模型结构和权重分离，部署时需要代码配合。

V2 用 `model.save_pretrained('models/')`，保存权重 + 模型配置（config.json）。加载时直接 `AutoModelForSequenceClassification.from_pretrained('models/')`，不需要提前建模型对象。更方便部署和分享。

## Q12: 项目还有什么可以改进的？

**标准答案（展示思考深度）：**

短期可以加**学习率调度器**（warmup + linear decay），训练更稳定。换 **AdamW** 替代 Adam，泛化更好。

中期可以做**数据增强**（同义词替换、回译），或**对抗训练**（FGSM/PGD）提升鲁棒性。

长期可以换更大的模型（RoBERTa-wwm-ext），或者做**模型蒸馏**用小模型部署，用 FastAPI 封装成 API。

代码层面，evaluate.py 有个变量命名问题（`train_loader` 应该是 `test_loader`），说明需要更好的代码审查习惯。
