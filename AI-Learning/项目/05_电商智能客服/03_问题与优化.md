# 电商智能客服系统 - 问题与优化

## 常见问题与解决方案

### 问题 1：LLM 意图识别不准确

**问题表现**：
- 用户说"退款"，LLM 识别为知识咨询
- 用户说"这个商品怎么样"，LLM 识别为任务流程

**原因分析**：
- 提示词不够清晰
- 对话历史过长导致上下文混乱
- 模型能力不足

**解决方案**：

| 方案 | 实现 | 效果 |
|------|------|------|
| 优化提示词 | 明确轨道定义、增加示例 | 中等 |
| 限制历史长度 | 只取最近 10 轮 | 减少干扰 |
| 使用更强模型 | qwen-plus → qwen-max | 显著提升 |

**优化路径**：
```
短期：优化提示词 + 限制历史长度
中期：添加 few-shot 示例
长期：微调意图分类模型
```

---

### 问题 2：幻觉输出（LLM 生成不存在的流程/意图）

**问题表现**：
- LLM 输出不存在的 flow_id
- LLM 输出未注册的 intent

**原因分析**：
- LLM 的"创造性"导致生成不存在的内容
- 提示词中未明确限制可选范围

**解决方案**：

| 方案 | 实现 | 效果 |
|------|------|------|
| 白名单校验 | TurnPlanValidator | ✅ 已实现 |
| 提示词约束 | 在 prompt 中列出所有可选值 | 辅助作用 |
| 结构化输出 | JSON Schema 约束 | 依赖模型能力 |

**优化路径**：
```
短期：白名单校验 + 澄清兜底 ✅
中期：使用 Function Calling 约束输出
长期：微调模型，减少幻觉
```

---

### 问题 3：响应延迟高（1-5 秒）

**问题表现**：
- 用户等待时间长
- 体感不佳

**原因分析**：
- LLM 调用耗时（1-3 秒）
- 多次 LLM 调用（TurnPlanner + ClarifyResponder）
- 网络延迟

**解决方案**：

| 方案 | 实现 | 效果 |
|------|------|------|
| 并发请求 | asyncio.gather | 中等 |
| 缓存常用意图 | Redis 缓存 TurnPlan | 显著 |
| 使用更快模型 | qwen-plus → qwen-turbo | 显著 |
| 流式输出 | SSE 流式返回 | 体感提升 |

**优化路径**：
```
短期：使用更快模型
中期：缓存常用意图
长期：流式输出 + 前端优化
```

---

### 问题 4：多轮对话状态丢失

**问题表现**：
- 用户说"刚才的订单"，系统不知道是哪个
- 任务中断后无法恢复

**原因分析**：
- 会话超时机制触发
- 状态序列化/反序列化出错
- 任务栈管理异常

**解决方案**：

| 方案 | 实现 | 效果 |
|------|------|------|
| 调整超时时间 | 60 分钟 → 更长 | 适应场景 |
| 状态校验 | 加载时校验完整性 | 防止出错 |
| 任务栈监控 | 记录栈操作日志 | 便于排查 |

**优化路径**：
```
短期：调整超时时间
中期：状态校验 + 容错处理
长期：状态版本管理 + 回滚机制
```

---

### 问题 5：知识检索召回率低

**问题表现**：
- 用户问常见问题，系统回答"未检索到相关信息"
- FAQ 和 RAG 占位实现

**原因分析**：
- 知识库为空
- 检索策略简单
- 没有向量化

**解决方案**：

| 方案 | 实现 | 效果 |
|------|------|------|
| 构建知识库 | FAQ 文档 + 产品文档 | 根本解决 |
| 向量化检索 | Embedding + 向量库 | 语义匹配 |
| 多路召回 | FAQ + RAG + API | 提升召回率 |
| Rerank | 重排序模型 | 提升精度 |

**优化路径**：
```
短期：填充 FAQ 知识库
中期：向量化检索 + 多路召回
长期：Rerank + 用户反馈优化
```

---

### 问题 6：槽位校验不完善

**问题表现**：
- 用户输入的订单号格式错误
- 系统没有校验直接执行

**原因分析**：
- YAML 流程中未定义 validation
- 校验规则简单

**解决方案**：

| 方案 | 实现 | 效果 |
|------|------|------|
| 添加 validation | YAML 中配置 condition | 中等 |
| 正则校验 | 订单号格式校验 | 精确 |
| LLM 校验 | 用 LLM 判断输入合理性 | 灵活 |

**优化路径**：
```
短期：添加基本 validation
中期：正则 + 业务规则校验
长期：LLM 校验 + 用户反馈
```

## 扩展路径

### 1. RAG 增强

```
当前：占位实现（FAQProvider、RAGProvider）
↓
扩展：
├─ 向量化检索：Embedding + Milvus/Chroma
├─ 多路召回：FAQ + 向量 + 关键词
├─ Rerank：重排序模型提升精度
└─ 知识库管理：文档切分、更新、版本控制
```

### 2. Agent 能力

```
当前：固定流程执行
↓
扩展：
├─ 动态工具调用：LLM 决定调用哪个 API
├─ 多步推理：Chain of Thought
├─ 自主决策：根据上下文动态调整策略
└─ 记忆机制：长期记忆 + 工作记忆
```

### 3. 多模态支持

```
当前：文本 + 对象消息
↓
扩展：
├─ 图片理解：用户发送商品图片
├─ 语音交互：语音转文字 + 文字转语音
├─ 视频客服：实时视频 + AI 辅助
└─ 表情/手势：非语言交互
```

### 4. 微调优化

```
当前：通用 LLM
↓
扩展：
├─ 意图分类微调：提升识别准确率
├─ 回复生成微调：更符合品牌调性
├─ 槽位提取微调：更准确的信息抽取
└─ 对话风格微调：更自然的交互
```

### 5. 生产级优化

```
当前：学习级实现
↓
扩展：
├─ 监控告警：LLM 调用成功率、延迟
├─ 灰度发布：新流程逐步上线
├─ A/B 测试：对比不同策略效果
├─ 日志分析：用户行为分析
└─ 容灾降级：LLM 不可用时的降级策略
```

| 无并发控制 | 状态冲突 | 低 | 添加乐观锁 |
