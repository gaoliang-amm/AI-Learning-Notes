# 02. 核心模块设计

## 1. 文档切分（split_service）

### 1.1 数据变换
```
md_content (整个MD文本) → chunks [{title, content, file_title, parent_title, part}]
```

### 1.2 三步切割流程

| 步骤 | 方法 | 输入 → 输出 | 规则 |
|------|------|------------|------|
| 粗切 | `split_chunks_document()` | `md_content` → `[{title, content}]` | 按 `#` 标题分割，保留代码块完整性 |
| 细切 | `_split_long_chunk()` | `content > 600` → `[{title_第N部分, content, parent_title}]` | 递归切割器，分隔符 `\n\n`→`\n`→`。`→`.` |
| 合并 | `_merge_short_chunks_same_parent_title()` | `content < 400` 的同标题块 → 合并 | 合并后不超过 1000 |

### 1.3 核心代码：标题粗切

```python
title_reg = re.compile(r"^\s*#{1,6}\s.+")  # 匹配 # 到 ######
chunks, current_title, current_title_lines = [], None, []
is_code_block = False

for line in md_content.split("\n"):
    line_strip = line.strip()
    if not line_strip:
        continue
    if line_strip.startswith("```") or line_strip.startswith("~~~"):
        is_code_block = not is_code_block  # 代码块内不识别标题
        current_title_lines.append(line_strip)
        continue
    if not is_code_block and title_reg.match(line_strip):
        if current_title and len(current_title_lines) > 1:
            chunks.append({"content": "\n".join(current_title_lines),
                           "title": current_title, "file_title": file_title})
        current_title = line_strip
        current_title_lines = [line_strip]
    else:
        current_title_lines.append(line_strip)
```

### 1.4 核心代码：递归细切

```python
splitter = RecursiveCharacterTextSplitter(

    chunk_overlap=CHUNK_OVERLAP,                 # 50
    separators=["\n\n", "\n", "。", "！", "？", "；", ".", "!", "?", ";"],

for part_index, split_text in enumerate(splitter.split_text(clear_content), start=1):

### 1.5 面试追问

**Q：chunk 600 怎么定的？**
→ 评估系统反复调试。600 字约 780 token，占 BGE-M3（8192）<10%；reranker 512 token 限制（问题+答案）。

**Q：overlap 为什么是 50？**
→ 8%-12%，太大重复干扰检索，太小语义断裂。

```python
# 1. 取前10个切片构建上下文
used_chunks = chunks[:CHUNKS_SPLIT_TOP_NUMBER]

for index, chunk in enumerate(used_chunks, start=1):

### 2.3 面试追问

**Q：为什么用 LLM 识别而不是正则？**
→ 产品手册格式多样，正则无法覆盖所有情况。LLM 能理解语义，从内容中提取隐含主体。

**Q：file_title 兜底什么意思？**
→ 如果 LLM 返回空（识别失败），用文件名作为 item_name，保证流程不中断。

## 3. BGE-M3 向量化

### 3.1 数据变换
```
texts: list[str] → result: {dense: list[list[float]], sparse: list[dict[int,float]]}
```

### 3.2 核心代码

```python
def generate_embeddings(texts):
    model = get_bge_m3_ef()  # 单例，首次加载
    embeddings = model.encode_documents(texts)

    # 稠密向量：直接转列表
    dense_list = [emb.tolist() for emb in embeddings["dense"]]

    # 稀疏向量：CSR格式 → {特征索引: 权重} 字典
    processed_sparse = []
    for i in range(len(texts)):
        indices = embeddings["sparse"].indices[
            embeddings["sparse"].indptr[i]:embeddings["sparse"].indptr[i + 1]
        ].tolist()
        data = embeddings["sparse"].data[
            embeddings["sparse"].indptr[i]:embeddings["sparse"].indptr[i + 1]
        ].tolist()
        processed_sparse.append({k: v for k, v in zip(indices, data)})

    return {"dense": dense_list, "sparse": processed_sparse}
```

### 3.3 面试追问

**Q：为什么 normalize_embeddings=True？**
→ L2 归一化后，Inner Product 和余弦相似度等价，Milvus 用 IP 检索更快，且混合检索时两路分数更容易融合。

**Q：sparse 向量为什么要转成 dict？**
→ Milvus 的 SPARSE_FLOAT_VECTOR 格式是 `{index: weight}`，模型输出的 CSR 格式需要转换。

## 4. 三路召回

### 4.1 向量检索（embedding_search）

```python
def search_by_milvus(item_names, rewritten_query):
    # 1. 问题向量化
    result = llm_providers.generate_embeddings([rewritten_query])
    # 2. 构建混合检索请求（dense + sparse 两路）
    reqs = milvus_gateway.create_requests(
        dense_vector=result['dense'][0],
        sparse_vector=result['sparse'][0],
        expr=f"item_name in {item_names}",  # 主体过滤
        limit=5 * 2
    )
    # 3. 执行混合检索
    milvus_result = milvus_gateway.hybrid_search(
        collection_name="kb_chunks", reqs=reqs,
        ranker_weights=(0.6, 0.4),  # 稠密0.6 + 稀疏0.4
        norm_score=True, limit=5,
        output_fields=["chunk_id", "title", "content", "item_name", "file_title"]
    )
    return milvus_result[0]
```

## 5. RRF 融合

### 5.1 数据变换
```
embedding_chunks [10个] + hyde_embedding_chunks [10个] → rrf_chunks [5个]
```

### 5.2 核心代码

```python
def use_by_rrf(rrf_list, top=5, k=60):
    score_dict, chunk_dict = {}, {}
    for weight, current_chunks in rrf_list:
        for rank, chunk in enumerate(current_chunks, start=1):
            chunk_id = chunk.get('chunk_id')
            # RRF 公式：score += weight * 1/(k + rank)
            score_dict[chunk_id] = score_dict.get(chunk_id, 0.0) + weight * (1 / (k + rank))
            chunk_dict.setdefault(chunk_id, chunk)  # 去重保留第一次出现的

    chunk_list = []
    for chunk_id, score in score_dict.items():
        chunk = chunk_dict[chunk_id]
        chunk["score"] = score
        chunk_list.append(chunk)

    chunk_list.sort(key=lambda x: x.get('score', 0), reverse=True)
    return chunk_list[:top]
```

### 5.3 面试追问

**Q：为什么不直接用 Milvus 的 RrfReranker？**
→ Milvus 的 RrfReranker 只能融合 Milvus 内部多路结果。我们的场景是融合"向量检索+HyDE"两路自定义结果，需要自己实现 RRF。同时 Milvus 的 RrfReranker 不支持自定义权重。

## 6. Rerank 精排

### 6.1 数据变换
```
rrf_chunks [5个] + web_search_docs [5个] → reranked_docs [2~6个]
```

### 6.2 核心代码：超长压缩 + 打分 + 动态截断

```python
def rerank_documents(state):
    rewritten_query, rrf_chunks, web_search_docs = get_data_and_validates(state)

    # 1. 统一数据格式
    reranker_docs = []
    for chunk in rrf_chunks:
        reranker_docs.append({"text": chunk["content"], "title": chunk["title"],
                              "score": 0, "type": "milvus", "url": None})
    for doc in web_search_docs:
        reranker_docs.append({"text": doc["snippet"], "title": doc["title"],
                              "score": 0, "type": "web", "url": doc.get("url")})

    # 2. 组装 [问题, 答案] 对，超长的用 LLM 压缩
    tokenizer = llm_providers.reranker_model().tokenizer
    q_tokens = len(tokenizer.encode(rewritten_query, add_special_tokens=False))
    pair_list = []
    for doc in reranker_docs:
        answer = doc["text"]
        a_tokens = len(tokenizer.encode(answer, add_special_tokens=False))
        if q_tokens + a_tokens + 4 > 512:  # reranker 上下文限制
            limit = max(50, int((512 - 4 - q_tokens) / 1.3))
            answer = (llm_providers.chat() | StrOutputParser()).invoke([
                HumanMessage(content=load_prompt("rerank_text_refine",
                               question=rewritten_query, answer=answer, limit=limit))
            ])
        pair_list.append([rewritten_query, answer])

    # 3. Reranker 打分
    scores = llm_providers.reranker_model().compute_score(pair_list, normalize=True)
    for score, doc in zip(scores, reranker_docs):
        doc["score"] = score
    reranker_docs.sort(key=lambda x: x.get("score", 0), reverse=True)

    # 4. 动态断崖截断
    for pre_index in range(1, 5):  # min_topk=2 到 max_topk=6
        abs_gap = reranker_docs[pre_index]["score"] - reranker_docs[pre_index + 1]["score"]
        ratio = abs_gap / reranker_docs[pre_index]["score"]
        if abs_gap > 0.2 or ratio > 0.2:
            reranker_docs = reranker_docs[:pre_index + 1]
            break

    state["reranked_docs"] = reranker_docs
    return state
```

def load_answer_prompt(state):
    question = state.get("rewritten_query")
    reranked_docs = state.get("reranked_docs", [])

    # 拼接上下文（带来源和置信度）
    context = ""
    for index, doc in enumerate(reranked_docs, start=1):
        source = "网络搜索" if doc.get("type") == "web" else "向量库"
        context += (f"第{index}部分,标题:{doc.get('title')},来源:{source},"
                    f"置信度:{doc.get('score')},内容:{doc.get('text')}\n")

    item_names = ",".join(state.get("item_names", []))
    history_text = get_history_text(state.get("session_id"))  # 从 MongoDB 获取

    return load_prompt("answer_out", question=question, context=context,
                       item_names=item_names, history=history_text)


def call_llm_deal_answer(state, answer_prompt_text):
    llm_client = llm_providers.chat()
    messages = [HumanMessage(content=answer_prompt_text)]

    if state.get("is_stream"):
        # 流式：逐 chunk 推送到 Queue
        answer = ""
        for chunk in llm_client.stream(messages):
            push_to_session(state["session_id"], SSEEvent.DELTA, {"delta": chunk.content})
            answer += chunk.content
    else:
        # 非流式：一次性返回
        answer = llm_client.invoke(messages).content

    state["answer"] = answer
```

### 7.3 图片 URL 提取

```python
def extract_text_image_url(state):
    image_re = re.compile(r"\!\[.*?\]\((.*?)\)")
    image_urls = []
    for doc in state.get("reranked_docs", []):
        # 从 url 字段提取
        if doc.get("url") and doc["url"].endswith((".jpg", ".png", ".gif", ".webp")):
            image_urls.append(doc["url"])
        # 从 text 中正则提取 markdown 图片链接
        urls = image_re.findall(doc.get("text", ""))
        if urls:
            image_urls.extend(urls)
    state['image_urls'] = image_urls
```

def select_item_names(milvus_result):
    confirmed_list, option_list = [], []
    for item_name, results in milvus_result.items():
        high = [r for r in results if r.get("score", 0) >= 0.70]   # 确认
        mid  = [r for r in results if 0.60 <= r.get("score", 0) < 0.70]  # 可选

        if high:
            confirmed_list.append(high[0])  # 取最高分
        elif mid:
            option_list.extend(mid[:2])  # 最多2个可选项

    return {"confirmed_list": confirmed_list, "option_list": option_list}


def apply_item_name_result(state, list_dict, rewritten_query):
    confirmed = list_dict.get("confirmed_list", [])
    option = list_dict.get("option_list", [])

    if confirmed:
        state['item_names'] = [i['item_name'] for i in confirmed]
        state['rewritten_query'] = rewritten_query
    elif option:
        state["answer"] = f"没有确认主体，相似可选：{','.join([i['item_name'] for i in option])}，请确认！"
    else:
        state['answer'] = "没有关联到任何主体，请明确后再提问！"
```
