# 03. 问题与优化

## 问题 1：弱语义查询召回率低

### 问题
用户问"这个怎么调"、"报警灯什么意思"——口语化、省略主体、语义稀疏，直接向量检索命中率低。

### 原因
短问句的语义信息不足，与知识库中标准化文档的向量表示差异大。

### 解决方案
- **HyDE 检索**：LLM 先生成假设答案，拼接问题+答案做检索输入，语义密度提升
- **问题改写**：LLM 结合历史对话，将口语化问题改写为标准查询
- **主体前置过滤**：先锁定 item_name，缩小检索范围

### 迭代路径
单路向量检索 → +问题改写 → +HyDE 增强 → +主体过滤 → 多路融合

---

## 问题 2：chunk 切分导致语义断裂

### 问题
固定长度切分会把一句话切成两半，导致检索命中后上下文不完整。

### 原因
机械切分不考虑语义边界。

### 解决方案
- **标题粗切**：按 `#` 标题做一级语义边界
- **递归细切**：用 LangChain RecursiveCharacterTextSplitter，按 `\n\n`、`\n`、`。` 等分隔符递归切分
- **短合并**：同标题下 <400 字符的 chunk 合并，上限 1000
- **overlap**：相邻 chunk 重叠 50 字符

### 迭代路径
固定长度 → 标题粗切 → +递归细切 → +短合并 → +overlap

---

## 问题 3：chunk 脱离全文后语义残缺

### 问题
切片脱离原文后，看不出在描述哪个产品/设备，导致检索时无法精准匹配。

### 原因
chunk 只有内容，缺少上下文标识。

### 解决方案
- **item_name 补全**：LLM 识别主体后回填到每个 chunk
- **标题路径保留**：title（当前标题）+ parent_title（父级标题）
- **向量化时拼接主体**：`item_name + content` 一起向量化

---

## 问题 4：Rerank 模型上下文长度不足

### 问题
BGE-reranker-large 上下文只有 512 token，长内容无法直接打分。

### 原因
模型架构限制（xlm-roberta，max_position_embeddings=514）。

### 解决方案
- **超长压缩**：问题+答案超过 512 token 时，用 LLM 压缩答案
- **压缩公式**：`limit = max(50, int((512 - 4 - question_len) / 1.3))`
- **压缩只用于打分**：原始内容用于最终生成答案

---

## 问题 5：固定 TopK 导致噪声或遗漏

### 问题
固定取 Top 5：有时前 3 个就很准，后面是噪声；有时前 5 个都不够。

### 原因
不同查询的相关性分数分布不同，固定 TopK 无法适配。

### 解决方案
**动态断崖截断**：检测相邻分数的分差，出现断崖时截断
- 绝对分差 > 0.2 → 截断
- 相对分差 > 20% → 截断
- 范围：min_topk=2 到 max_topk=6

## 问题 6：并发节点 State 冲突

### 问题
三路召回并行执行时，都返回 `session_id`，导致 `InvalidUpdateError`。

### 原因
LangGraph 并发节点默认不能写入相同的 key。

### 解决方案
- 并发节点只返回自己修改的 key（如 `embedding_chunks`、`hyde_embedding_chunks`、`web_search_docs`）
- 公共字段（如 `session_id`）不在并发节点中返回

---

## 问题 7：流式输出任务状态不准确

### 问题
第二次提问时，节点状态上来就是"已完成"——是上一次的缓存结果。

### 原因
task_utils 的三个状态字典是全局的，跨请求共享。

### 解决方案
每次请求前清空状态：`clear_task(session_id)` + `create_sse_queue(session_id)`

---

## 问题 8：Milvus 检索注入风险

### 问题
item_name 包含特殊字符（如单引号）时，Milvus filter 表达式会出错。

### 解决方案
`escape_milvus_string()` 对 item_name 做转义处理。

## 扩展路径

### 当前系统 → Agent 增强
- 将确定性节点替换为 Agent 决策节点
- 增加工具调用能力（数据库查询、API 调用）
- 保留 LangGraph 的状态管理和流程控制

### 当前系统 → RAG 增强
- 增加 Query Decomposition（复杂问题拆解）
- 增加 Self-RAG（自我反思和纠错）
- 增加多轮对话的上下文压缩

### 当前系统 → 生产级
- 增加缓存层（Redis 缓存热门查询）
- 增加限流（Rate Limiting）
- 增加 A/B 测试框架
- 增加日志分析和监控告警
