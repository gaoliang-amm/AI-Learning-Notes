# 掌柜问数 — 问题与优化

> [!abstract] 踩坑记录、优化路径、以及如何扩展到生产级系统。

---

## 1. 常见问题与解决方案

### 1.1 召回不准确

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| "销售额" 匹配不到 `order_amount` | jieba 字面分词无法理解同义词 | LLM 语义扩展关键词，补充"订单金额"等同义词 |
| "华北" 匹配不到具体值 | 向量召回对短文本精确匹配效果差 | 用 ES 全文索引做字段值召回，IK 分词器匹配 |
| 召回了太多不相关的表/字段 | 向量召回阈值太低，噪音多 | 增加 `score_threshold`（如 0.6），LLM 二次过滤 |

### 1.2 SQL 生成错误

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| 表名/字段名写错 | LLM 幻觉，编造不存在的表名 | EXPLAIN 校验 + LLM 校正闭环 |
| JOIN 条件缺失 | LLM 不知道表之间的关联关系 | 在 prompt 中提供表的主键/外键信息 |
| WHERE 条件逻辑错误 | 用户问题理解偏差 | 补充字段的 examples 和 alias，让 LLM 更好理解 |

### 1.3 性能问题

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| 整体响应慢（>5s） | 多次 LLM 调用 + 向量搜索 | 流式输出进度，用户体验上不觉得慢 |
| 向量搜索慢 | 数据量增长后 Qdrant 查询变慢 | 增加 Qdrant 节点数，优化索引参数 |
| ES 搜索慢 | 字段值数据量大 | 限制 ES 索引的字段范围（sync=true） |

### 1.4 数据质量问题

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| 元数据不完整 | 配置文件遗漏了某些表/字段 | 定期审查 meta_config.yaml，补充新表 |
| 指标定义模糊 | "销售额"和"订单金额"含义不清 | 在 metric_info 中明确计算口径和别名 |

## 2. 优化路径

### 2.1 检索质量优化

```
当前：jieba + LLM 扩展 → 向量/全文召回 → LLM 过滤
优化：+ Rerank 重排序 → + HyDE 假设文档检索 → + Few-shot SQL 示例
```

- **Rerank**：召回后用 BGE-Reranker 对结果重排序，提升 top-K 精度
- **HyDE**：让 LLM 先生成一个假设的 SQL，再用 SQL 中的表/字段名去检索
- **Few-shot**：在 prompt 中提供类似的 SQL 示例，引导 LLM 生成更准确的 SQL

### 2.2 SQL 生成优化

```
当前：单次生成 + EXPLAIN 校验 + 单次校正
优化：+ SQL 策略路由 → + 多候选投票 → + 执行结果验证
```

- **SQL 策略路由**：根据问题类型（聚合/过滤/JOIN）选择不同的 prompt 策略
- **多候选投票**：生成 3 个 SQL 候选，用 EXPLAIN 校验后选择最优
- **执行结果验证**：执行 SQL 后检查结果是否合理（如空结果、异常值）

### 2.3 工程化优化

```
当前：单机部署，内存存储
优化：+ Redis 缓存热门查询 → + 异步任务队列 → + 监控告警
```

- **缓存**：相似问题的 SQL 结果缓存到 Redis，减少重复计算
- **异步队列**：高并发时将查询请求放入队列，削峰填谷
- **监控**：记录每次查询的耗时、SQL、结果，便于分析和优化

## 3. 扩展路径

### 3.1 扩展到 Agent 系统

当前是 Workflow 系统（预定义流程），可以升级为 Agent 系统（自主决策）：

```
当前：固定 12 节点流程
扩展：LLM 自主决定是否需要召回、召回几次、是否需要校正
```

- 用 LangGraph 的 `Tool Calling` 让 LLM 自主选择工具
- 动态决定召回次数（一次不够就再召回一轮）
- 支持多轮对话（用户追问"按月看呢？"）

### 3.2 扩展到多模态

```
当前：纯文本 NL2SQL
扩展：+ 图表理解 → + 自然语言查询图表数据
```

- 用户上传 Excel/CSV，自动识别字段和类型
- 生成 SQL 后自动选择可视化方式（表格/折线图/柱状图）

### 3.3 扩展到生产级

```
当前：原型系统
扩展：+ 用户认证 → + 权限控制 → + SQL 白名单 → + 审计日志
```

- **SQL 白名单**：只允许 SELECT 查询，禁止 DELETE/DROP
- **权限控制**：不同用户只能查询授权的数据范围
- **审计日志**：记录所有 SQL 和查询结果，便于追溯
